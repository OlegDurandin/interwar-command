# Interwar Command

Пошаговый варгейм на гексах с редактором карт и двумя операциями. В меню «Сценарии» доступны учебная «Переправа» и «Варшавское предмостье» по мотивам событий августа 1920 года. В учебной «Переправе» можно командовать синими или красными против ИИ либо играть за обе стороны на одном экране. Боевые приказы, снабжение и результат рассчитывает Rust через WASM. [Крупный план переправы](docs/previews/crossing-detail-illustrated.png) · [Игровой экран](docs/previews/crossing-desktop-illustrated.png) · [Портрет](docs/previews/crossing-portrait-illustrated.png).

## Попробовать бой на Mac

В уже настроенной рабочей копии остановите прежний Vite сочетанием Ctrl+C. Из корня запустите `pnpm dev`, чтобы собрать обновлённый Rust/WASM. Откройте локальный адрес из вывода Vite.

1. В меню нажмите «Начать», выберите «Синие · против ИИ», затем «Начать операцию». Выберите синюю кавалерию в (2, 1). Щёлкните по золотой клетке (4, 2). Кавалерия сразу займёт её. Чтобы заранее посмотреть путь и стоимость, нажмите «Маршрут» в карточке части, затем выберите клетку.
2. Нажмите красную пехоту в (5, 2). В карточке появятся диапазоны потерь и вклад штаба, снабжения, местности, окопов и реки. Кнопка «Атаковать» применяет приказ.
3. Под картой можно включить «Прогноз снабжения на следующую фазу». Он показывает доступность клеток для текущей стороны. Цветная полоска на фишке и значение в карточке показывают снабжение, с которым часть сейчас вступает в бой.

После «Завершить фазу» противник отдаст свои приказы, затем начнётся следующий раунд. Автосохранение фиксируется после каждого принятого приказа. После перезагрузки выберите «Продолжить партию». «Сохранить позицию» создаёт отдельную ручную запись. Сохранения привязаны к адресу и профилю браузера.

## Проверить мобильный экран на самом Mac

1. Запустите `pnpm dev` в корне проекта и откройте адрес Vite в Chrome.
2. Откройте DevTools сочетанием `⌥⌘I`. Нажмите значок телефона и планшета (Toggle device toolbar), выберите профиль iPhone с сенсорным вводом, например iPhone 12 Pro (390 × 844), и обновите страницу. [Мобильный режим Chrome](https://developer.chrome.com/docs/devtools/device-mode/).
3. Откройте «Начать» → «Синие · против ИИ» → «Начать операцию». Выберите пехоту в (1, 2). Для проверки просмотра нажмите «Маршрут», укажите (3, 2) и нажмите «Отмена». Пехота должна остаться в (1, 2).
4. При любом масштабе нажмите золотую клетку (4, 2). Пехота должна занять её сразу. Нажмите красную пехоту в (5, 2), поверните экран значком Rotate и проверьте, что кнопки «Отмена» и «Атаковать» доступны. Для проверки жестов пальцами откройте ту же сборку на телефоне по инструкции ниже.

## Открыть на телефоне с Mac

Подключите телефон и Mac к одной сети Wi-Fi. В настроенной рабочей копии выполните от своего пользователя:

```sh
pnpm build
pnpm --filter @interwar/web exec vite preview --host 0.0.0.0 --port 4173 --strictPort
```

Откройте на телефоне адрес `Network` из терминала Mac, например `http://192.168.1.25:4173`. Оставьте терминал открытым на время игры. Для остановки нажмите Ctrl+C.

1. Начните «Переправу» за синих. Коснитесь своей пехоты в (1, 2), затем выделенной клетки (4, 2). Часть перемещается одним касанием клетки назначения при любом масштабе и остаётся выбранной. Для просмотра пути до хода нажмите «Маршрут», затем коснитесь клетки. Выберите «Отмена» или подтвердите перемещение.
2. Коснитесь красной пехоты в (5, 2) и поверните телефон. В портрете карточка находится под картой, в альбомной ориентации — справа. Прокрутите прогноз, отмените приказ или нажмите «Атаковать».
3. Потяните карту одним пальцем, измените масштаб двумя или дважды коснитесь своей части для центрирования. Во вкладке «Слои» также есть кнопки масштаба. «Части» открывает список фишек, «Сводка» — цели и журнал, «Запись» — сохранения.
4. Сверните браузер и вернитесь. Проверьте выбранную часть, раунд и доступность кнопки «Завершить фазу». После завершения фазы за противника сыграет ИИ.

## Telegram Mini App

В настроенной копии на Mac выполните `pnpm test:telegram`. Команда собирает клиент, получает официальный `telegram-web-app.js` и запускает партию в Chromium с тестовым хостом Telegram. Для работы без сети можно указать сохранённую копию официального SDK в переменной `INTERWAR_TELEGRAM_SDK_FILE`. Основные браузерные тесты `pnpm check` доступны с уже установленными зависимостями без загрузки SDK.

**Проверка в самом Telegram.** Для тестового бота нужен доступный с телефона HTTPS-адрес сборки. Результат `pnpm build` находится в `apps/web/dist`; хостинг должен отдавать файл `.wasm` с типом `application/wasm`. Укажите HTTPS-адрес корня сборки для кнопки меню тестового бота через `/setmenubutton` в @BotFather. Затем в чате с ботом откройте кнопку меню. Обычная ссылка в сообщении может открыть встроенный браузер. [Кнопка Mini App в документации Telegram](https://core.telegram.org/bots/webapps#launching-mini-apps-from-the-menu-button).

1. Откройте настройки и вернитесь системной кнопкой «Назад». Начните «Переправу» за синих.
2. Переместите пехоту в (4, 2), коснитесь красной пехоты в (5, 2) и поверните экран. Проверьте, что меню Telegram и вырез экрана оставляют доступ к кнопкам боя. Нажмите «Назад», ещё раз выберите цель и подтвердите атаку.
3. Передайте фазу ИИ, сверните Mini App, затем откройте её снова. Проверьте продолжение партии, итоговый экран и восстановление после закрытия и повторного запуска приложения. Запишите версию Telegram, устройство и ОС для таблицы в PROGRESS.

Для одиночной партии достаточно локального IndexedDB. Обычный браузер и Telegram могут использовать разные хранилища для одного адреса.

## Варшавское предмостье

В главном меню нажмите «Сценарии», выберите «Варшавское предмостье» и сторону, затем «Начать операцию». Первая фаза принадлежит Красной армии. При игре за Войско Польское её проведёт ИИ. Цели — Радзымин и Оссув. Условия победы, период и источники доступны в карточке сценария. [Описание и исторические допущения](content/scenarios/README.md#варшавское-предмостье).

## Редактор карт

Откройте «Редактор сценариев» в главном меню на ПК или добавьте `?editor` к адресу клиента. «Новая карта» задаёт ширину и высоту. В «Копии „Переправы“» уже есть обе стороны, источники и цель. Выберите гекс на карте, затем инструмент в правой панели. Для ребра отметьте соседний гекс, переключите нужные признаки и нажмите «Применить к ребру». Для переноса части выберите её по ID, щёлкните по новой стартовой клетке и нажмите «Разместить».

«Отменить» и «Повторить» работают для 50 последних правок. «Проверить» показывает замечания общего валидатора. «Экспорт JSON» сохраняет проверенный сценарий в файл, «Открыть JSON» загружает его обратно. «Тестовая партия» открывает текущий черновик с управлением обеими сторонами. Нажмите «Вернуться в редактор», чтобы продолжить с авторской расстановки. Черновик живёт до закрытия страницы. Перед выходом экспортируйте его в файл.

## VK Mini Apps

Установите зависимости из корня проекта. Для обычного браузера запустите `pnpm dev`. Команда `pnpm test:vk` собирает production-клиент и проверяет его с официальным `@vkontakte/vk-bridge@3.0.2`, эмуляцией ответов VK, настоящим WASM и IndexedDB.

```sh
pnpm install --frozen-lockfile
pnpm test:vk
```

**Открытие на телефоне.** Разместите содержимое `apps/web/dist` в корне доступного телефону HTTPS-сайта. Этот каталог создают и `pnpm test:vk`, и `pnpm build`. Хостинг должен отдавать `.wasm` с типом `application/wasm` и разрешать встраивание страницы во фрейм VK для веб-клиента.

1. В кабинете разработчика VK откройте своё тестовое мини-приложение или создайте его. В настройках включите режим разработки, укажите HTTPS-адрес сборки в поле «URL для разработки» для проверяемых платформ и сохраните. [Инструкция VK](https://github.com/VKCOM/vk-mini-apps-course-frontend).
2. В мобильном приложении ВКонтакте под аккаунтом с доступом к тестовой версии откройте `https://vk.com/app<ID>`, подставив числовой ID. «Начать» → «Синие · против ИИ» → «Начать операцию».
3. Коснитесь синей пехоты в (1, 2), затем клетки (4, 2). Коснитесь красной пехоты в (5, 2), проверьте прогноз и нажмите «Атаковать».
4. Завершите фазу. Дождитесь раунда 2 и активной стороны «Синие». Откройте «Запись», дождитесь статуса «Сохранено» и запомните позиции во вкладке «Части». Перезагрузите мини-приложение, нажмите «Продолжить партию» и сверьте раунд, сторону и позиции обеих сторон. Для проверки используйте тот же клиент, аккаунт и адрес сборки.

## Установка

Выполняйте команды из корня локальной рабочей копии. Для первой установки нужен доступ к реестрам Cargo и npm и источникам бинарных инструментов. Для Rust нужен системный линкер. В Windows установите Visual Studio Build Tools с инструментами MSVC C++ для архитектуры хоста и Windows SDK. Запускайте команды в Developer PowerShell для этой архитектуры.

В Windows при работе с диском VirtualBox Shared Folders (в этой рабочей копии `Y:`) выполните в корне проекта перед установкой и запуском команд:

```powershell
$env:NPM_CONFIG_WORKSPACE_DIR = (Get-Location).Path
$env:npm_config_node_linker = 'hoisted'
$env:CHOKIDAR_USEPOLLING = 'true'
$env:CARGO_TARGET_DIR = Join-Path $env:LOCALAPPDATA 'interwar-command/target'
```

Первая переменная сохраняет букву сетевого диска при обнаружении workspace. Режим `hoisted` позволяет обойти ограничение VirtualBox на создание каталогов-ссылок, polling обеспечивает наблюдение Vite за изменениями файлов. Cargo использует локальный каталог для промежуточных файлов и исполняемых тестов. На обычном локальном диске действует стандартная установка pnpm.

1. Установите [rustup](https://rustup.rs/) и [Node.js 22.16.0](https://nodejs.org/dist/v22.16.0/). Если используете nvm, выполните `nvm install 22.16.0` и `nvm use 22.16.0`.
2. Установите Rust с WASM target, wasm-pack и pnpm:

   ```sh
   rustup toolchain install 1.100.0 --profile minimal --component rustfmt,clippy --target wasm32-unknown-unknown
   cargo install wasm-pack --version 0.13.1 --locked
   npm install --global pnpm@10.11.1
   ```

   Можно также распаковать [wasm-pack 0.13.1](https://github.com/rustwasm/wasm-pack/releases/tag/v0.13.1) в каталог из `PATH`. Проверьте `rustc --version`, `wasm-pack --version`, `node --version` и `pnpm --version`. Для сборки требуется доступный из shell исполняемый файл `wasm-pack`.

3. Первый запуск установки выполняется командой `pnpm install`. Для воспроизводимой установки из сохранённого lockfile выполните `pnpm install --frozen-lockfile`. В репозитории закреплены версии в `rust-toolchain.toml`, `.node-version`, манифестах пакетов, `Cargo.lock` и `pnpm-lock.yaml`.
4. Установите браузер для тестов:

   ```sh
   pnpm --filter @interwar/web --fail-if-no-match exec playwright install chromium
   ```

   На Linux с отсутствующими системными библиотеками используйте `playwright install --with-deps chromium` через тот же `pnpm --filter @interwar/web --fail-if-no-match exec`.

### Повторный запуск на macOS

После установки зависимостей откройте терминал в каталоге `interwar-command` и выполните `pnpm dev` от своего пользователя. Если при установке пакетов возникает `ENOMEM`, повторите загрузку с одним сетевым запросом за раз, используя уже скачанные пакеты:

```sh
npm_config_network_concurrency=1 pnpm install --frozen-lockfile --prefer-offline
```

## Запуск и проверка

```sh
pnpm dev
```

Откройте адрес Vite из терминала (обычно `http://127.0.0.1:5173`). На первом запуске wasm-pack подготавливает CLI wasm-bindgen версии из Cargo.lock. После выбора «Синие» и старта операции выделена пехота в (1, 2). Щёлкните по (3, 2). Пехота переместится туда, а в карточке будет показан пройденный путь через (2, 2). Техническая карта 10×8 доступна по ссылке «Тестовая сетка».

| Команда из корня | Результат |
|---|---|
| `pnpm wasm:build` | Выполняет `wasm-pack build crates/game-wasm --target web --out-dir pkg` |
| `pnpm dev` | Генерирует WASM и запускает Vite |
| `pnpm typecheck` | Генерирует WASM и объявления, затем выполняет `tsc --noEmit` |
| `pnpm lint` | ESLint для приложения, тестов и конфигурации TS |
| `pnpm test` | Нативные тесты Rust, проверка схемы сценария и Vitest для геометрии renderer и истории редактора |
| `pnpm build` | Подготавливает WASM, проверяет типы и создаёт `apps/web/dist` |
| `pnpm test:schema` | Проверяет оба встроенных сценария и ошибки формата v1 (Ajv) |
| `pnpm test:wasm` | Собирает WASM и сверяет хеш состояния и журнала с нативным эталоном партии |
| `pnpm test:e2e` | Собирает клиент, запускает Vite preview на `127.0.0.1:4173` и проверяет карту в Chromium |
| `pnpm test:vk` | Production-сборка, выбор платформы, эмуляция транспорта VK и восстановление партии через интерфейс |
| `pnpm test:telegram` | Production-сборка и проверка с официальным SDK, профилями возможностей 6.0 и 8.0 и эмуляцией нативных событий |
| `pnpm check` | Rust fmt/clippy, unit-тесты обоих языков, lint, typecheck, production build и browser smoke |

Чтобы открыть production-сборку вручную, выполните `pnpm build`, затем `pnpm --filter @interwar/web --fail-if-no-match exec vite preview --host 127.0.0.1`. Браузеру требуется WebGL. В smoke test Playwright запускает и останавливает собственный preview, для него нужен свободный порт 4173.

Для дополнительной проверки мобильного маршрута в WebKit из корня выполните:

```sh
pnpm --filter @interwar/web exec playwright install webkit
pnpm build
pnpm --filter @interwar/web exec playwright test mobile.spec.ts --browser=webkit --workers=1
```

Отдельные проверки Rust:

```sh
cargo fmt --all --check
cargo test --workspace
cargo clippy --workspace --all-targets -- -D warnings
```

## Проверка сценария без браузера

```sh
cargo run --locked -p game-core --example validate_scenario -- content/scenarios/crossing.json
```

Для «Переправы» ожидается `training_crossing: 8x5, units=6, objectives=1`. Чтобы проверить другой файл, передайте его путь последним аргументом. Этот же файл загружается ядром при открытии веб-клиента. Формат v1 и диагностика описаны в [справочнике сценариев](docs/SCENARIO_FORMAT.md).

## Проверка фаз партии

Из корня выполните `cargo test --locked -p game-core --test game`. Тесты запускают «Переправу» без браузера, отдают приказы окапывания и завершения фазы и проверяют счёт, события и результат партии.

## Устройство проекта

| Путь | Назначение |
|---|---|
| `crates/game-core` | Геометрия Hex, карта, загрузчик сценария, состояние партии, команды и журнал событий |
| `crates/game-wasm` | Типизированная сессия, приказы, журнал, сохранение, загрузка и следующий приказ ИИ через wasm-bindgen. Сгенерированные JS, типы и бинарный модуль появляются в игнорируемом каталоге `pkg` |
| `crates/game-ai` | Детерминированный соперник через публичный API ядра |
| `apps/web/src/game` | Меню, штабной экран, карточка приказа, фаза ИИ и очередь сохранений IndexedDB |
| `apps/web/src/platform` | Обнаружение хоста, официальные SDK Telegram и VK, viewport, жизненный цикл и системная кнопка «Назад» |
| `apps/web/src/editor` | Редактор документа, инструменты карты и история правок |
| `apps/web/src/renderer` | Рисование PixiJS, выбор по пикселям и камера |
| `apps/web/e2e` | Браузерная проверка production-сборки |
| `content/scenarios` | «Переправа», «Варшавское предмостье» и исторические источники |

Границы модулей и жизненный цикл описаны в [архитектуре](docs/ARCHITECTURE.md). Нормативные требования находятся в [SPEC.md](SPEC.md), объём первого этапа — в [FIRST_TASK.md](FIRST_TASK.md), фактические результаты — в [PROGRESS.md](PROGRESS.md). [AGENTS.md](AGENTS.md) задаёт правила разработки.
