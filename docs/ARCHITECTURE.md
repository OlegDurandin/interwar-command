# Ядро и веб-клиент

`game-core` оперирует axial-координатами `i32`. Расстояние возвращается как `u64`, включая пары крайних значений координат. Каждый из шести слотов `neighbors()` соответствует направлению из SPEC §5.1. За пределами представимого диапазона слот равен `None`. Размер тестового листа ограничивает выбор в renderer.

`Map::new` принимает размеры, значения по умолчанию, переопределения клеток и рёбра. Конструктор проверяет размеры перед выделением памяти, применяет переопределения к плотному массиву и затем проверяет рёбра по итоговой местности. Ошибка содержит `MapErrorKind` и путь к исходному полю. Загрузчик `scenario::load_scenario` разбирает ограниченный по размеру JSON v1, проверяет ссылки контролёров на фракции и вызывает этот конструктор. По нормализованной карте он проверяет размещение частей, источники и цели, затем возвращает сценарий с предупреждениями. Файловый ввод находится в примере CLI. Формат данных описан в [SCENARIO_FORMAT.md](SCENARIO_FORMAT.md).

Публичный API адресует клетки через `Hex`. Итератор `tiles()` обходит строки в порядке `(r, q)`, а `edges()` выдаёт записи по каноническим концам. Для соседней пары на суше `edge_features()` возвращает признаки перехода, включая обычный переход со всеми флагами `false`. Для недопустимой пары он возвращает `None`.

`game-wasm` экспортирует `hex_distance(q, r, other_q, other_r)`. Функция делегирует вычисление ядру. Сгенерированный wasm-bindgen контракт принимает четыре числа и возвращает `bigint`. UI передаёт целые координаты выбранной клетки и преобразует результат в строку для отображения.

Корневая команда подготавливает `crates/game-wasm/pkg` до запуска Vite или TypeScript. Клиент импортирует сгенерированный ES-модуль. Vite обрабатывает URL бинарного файла относительно модуля и выпускает отдельный ассет. В dev доступ к нему обеспечивает штатная граница pnpm workspace.

React ожидает общий Promise инициализации WASM перед запуском карты. После асинхронной подготовки WebGL приложение PixiJS рисует лист и выделение. Обработчики указателя и ResizeObserver работают в координатах canvas. Renderer переводит их в мировые координаты и передаёт выбранный гекс в React. Камера и дробное округление пикселей принадлежат renderer.

При размонтировании AbortController отключает ввод. Cleanup отсоединяет наблюдатель размеров и уничтожает приложение PixiJS с canvas и дочерними объектами. Если инициализация завершилась уже после размонтирования, созданное приложение сразу освобождается. Ошибки загрузки ядра и открытия WebGL выводятся в панели состояния.

`game-ai` выбирает следующую команду по публичному состоянию, вариантам движения и предпросмотру. Браузер исполняет не более одной команды за вызов таймера и отправляет её тем же путём, что и человеческий приказ. Во время фазы противника ввод игровых приказов заблокирован. Журнал самой партии определяет использованный бюджет фазы, включая продолжение после загрузки.

## Нативная партия

`GameState::load(bytes)` использует общий загрузчик сценария и готовит состояние `NotStarted`. Партия хранит исходный сценарий и отдельно изменяемые данные частей. `start()` открывает первый раунд для `starting_faction_id` с ревизией 0 и пустым журналом команд. Повторный старт возвращает ошибку.

Изменения проходят через `apply_action(GameAction)`. `Entrench` поднимает уровень окопов активной части на один, до двух, и расходует приказ. Флаги сбрасываются при начале следующей фазы владельца. `EndPhase` после A передаёт фазу стороне B. После B ядро закрывает раунд, обрабатывает цели в порядке ID и начинает следующую фазу A либо фиксирует итог партии. При создании партии обе стороны получают исходное снабжение. В начале фазы ядро пересчитывает уровень для частей активной стороны, корректирует готовность и сбрасывает флаги.

Каждый принятый приказ добавляет одну команду и одну ревизию. `ActionResult` возвращает срез событий этой команды. События содержат типизированные факты, ревизию и порядковый номер с нуля. Неудачная команда возвращает `GameError` до изменения состояния. Ядро принимает четыре команды из SPEC §12.5. `MovementSession.apply_action` принимает `GameOrder` и возвращает упорядоченные события и новую ревизию. Сохраняются специализированные методы движения и боя для карточек приказа.

## Предпросмотр движения T-005

Стартовый экран создаёт `MovementSession` из JSON «Переправы». Сессия владеет `GameState`, а при размонтировании React освобождает её. Типы снимков и маршрутов генерируются из Rust. PixiJS отображает нормализованные клетки, рёбра, текущий контроль и части. Касание или щелчок по доступной клетке при любом масштабе выдаёт один приказ движения после отпускания указателя. Renderer отсеивает перетаскивание, pinch и прерванное касание. Только при включённом кнопкой «Маршрут» просмотре интерфейс показывает путь из `GameState::reachable`. Можно сравнить другие назначения, отменить просмотр или подтвердить приказ. В обоих случаях после `apply_action(Move)` интерфейс получает фактически пройденный путь и обновляет снимок. Камера сохраняет своё положение.

Движение использует очередь по (стоимость, r, q) и снимок занятости и ZOC до приказа. Текущий контролёр берётся из изменений партии с возвратом к данным сценария для остальных клеток. Этим же методом пользуется начисление очков. Отдельная тестовая карта T-001 доступна по адресу `/?demo`. `options` возвращает маршруты, допустимые цели с предпросмотром и доступность окапывания одним вызовом.

## Бой и снабжение

`game/combat.rs` проверяет приказ и формирует одинаковые исходные условия для предпросмотра и атаки. Предпросмотр перебирает девять сочетаний бросков. Приказ применяет одновременные потери, уничтожение и продвижение, используя seed сценария и индекс боя. Интерфейс получает диапазоны, модификаторы и фактические потери из Rust.

`game/supply.rs` строит карту минимальных стоимостей из действующих источников. Движение и снабжение используют одну функцию вражеской зоны контроля. Только создание партии и начало фазы записывают уровень в часть. Прогноз картографического слоя строится при чтении снимка.

## Графика оперативной карты

Меню, командный экран и редактор используют один `OperationLayer` в PixiJS. Рельеф, лес и поля отрисовываются по типу и координатам клетки. Рисунок участка выбирает целочисленный хеш координат. Дорога, шпалы, русло и настил читают одни и те же флаги ребра. Камера и обработчик выбора по полному гексу общие для обоих представлений частей.

Атлас `countryside.webp` содержит шесть иллюстраций местности, созданных ImageGen по художественному ориентиру `gameplay_preview.jpg`. Луг и поле служат вариантами равнины. Остальные кадры изображают лес, застройку, холм и болото. Вода в клетке рисуется отдельно. Изображения имеют прозрачный контур гекса и общий источник текстур. Смена выделения, управляющей стороны или прогноза снабжения сохраняет спрайты местности. Соседние участки реки соединяются в общих вершинах, а середина ребра привязывает мост к руслу.

Атлас `apps/web/src/renderer/assets/interwar-miniatures.webp` нарезан из предоставленного PNG «Межвоенная пехота, кавалерия, орудие и штаб-2». Четыре типа миниатюр имеют индивидуальную точку опоры. Дополнительный кадр штаба сохраняет рисунок и складки вымпела для второй стороны. Текстуры разделяют один источник изображения. При ширине гекса менее 37 CSS px или до загрузки атласа используются компактные знаки. Смена масштаба через этот порог обновляет только слой частей.

## Редактор и каталог сценариев

Маршрут `?editor` загружает desktop-редактор по требованию. Черновик хранит документ сценария v1 и до 50 обратимых изменений. Камера, выбор гекса и отрисовка местности, рёбер и частей общие с партией. Незаконченный черновик можно рисовать до расстановки источников и целей. Импорт, экспорт и запуск партии проходят через WASM-функцию `validate_scenario`, вызывающую `game_core::scenario::load_scenario`; ошибка содержит путь в исходном документе.

Игровой каталог передаёт выбранный JSON существующему `MovementSession`. При возврате к сохранённой операции её исходная карта берётся из вложенного сценария. Редактор передаёт в тот же командный экран отдельную копию документа, удерживая черновик и историю в памяти. В этом режиме командный экран не обращается к автоматическому и ручному слотам IndexedDB.

## Платформы браузера, Telegram и VK

`apps/web/src/platform` связывает оболочку React и события WebView. Обычный браузер использует собственный viewport и события видимости. Адаптер подключает официальный SDK при наличии нативного транспорта или родительского фрейма Telegram Web. В режиме совместимости с `external.notify` дополнительно проверяется признак запуска Mini App. Обнаружение хоста используется только для UI. [Telegram Mini Apps](https://core.telegram.org/bots/webapps) · [Транспорты Telegram](https://core.telegram.org/api/web-events#event-apis).

Для VK проверяется нативный транспорт или родительский фрейм VK. Общему транспорту React Native дополнительно нужны параметры запуска VK. Клиент загружает модуль `platform/vk/bridge` по требованию и включает платформенные возможности после подтверждения `VKWebAppInit`. Отступы и видимость поступают через подписку моста, доступность дополнительных методов проверяется через `supportsAsync`. Пока хост обрабатывает запросы, меню и локальные сохранения работают самостоятельно. [Официальный VK Bridge](https://github.com/VKCOM/vk-bridge) · [Навигация в VK Mini Apps](https://vkui.io/integrations/vk-mini-apps/#навигация).

Кнопкой «Назад» управляет активный экран. Адаптер объединяет сигналы видимости документа и активности клиента, чтобы остановить очередь ИИ и сбросить незавершённый жест. После возврата очередь возобновляется из текущей сессии. Размер карты обновляет существующий ResizeObserver. Платформенные данные хранятся отдельно от состояния Rust и формата сохранений.

## Сохранение и воспроизведение

`GameState::serialize_save` включает канонический сценарий, изменяемое состояние и историю. `load_save` проверяет версии, контрольные суммы, положение частей, фазу и счёт, затем восстанавливает поля напрямую. Нативный replay отдельно исполняет команды с начала партии. Golden fixture в `crates/game-core/tests/crossing-replay.json` используется и Rust-тестом, и собранным WASM.

В браузере поверх Rust-сохранения хранится выбранная сторона человека. В IndexedDB есть отдельные записи для автоматической и ручной позиции. Записи выполняются последовательно. Сравнение предыдущего значения внутри транзакции выявляет изменение другой вкладкой. Индикатор подтверждает запись в обработчике завершения транзакции. [Решение по формату](adr/0001-save-format.md).
