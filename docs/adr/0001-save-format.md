# ADR 0001. Снимок партии и воспроизводимый журнал

Принято 18.11.2026 для T-008 и T-013. Нормативные требования заданы в [SPEC §§12.4–12.5](../../SPEC.md).

Сохранение версии 1 встраивает нормализованный сценарий. Клетки сценария и контролёры снимка следуют в порядке строк, концы рёбер канонизируются, а живые части и очки адресуются по ID. Канонические JSON-объекты сортируются по ключам до расчёта SHA-256. Версии и хеш сценария входят в состояние. Раздельная сумма журнала покрывает массивы команд и событий в исходном порядке. Десятичные строки сохраняют точность счётчиков при обмене с JavaScript.

Загрузка проверяет версии, целостность и инварианты снимка, затем восстанавливает текущую фазу напрямую. Это позволяет открыть позицию внутри фазы с ранее рассчитанным снабжением. Отдельный replay запускает сценарий с начала и исполняет журнал через обычный валидатор. Эталон «Переправы» фиксирует ожидаемые хеши для Rust и WASM.

Оболочка сохраняет вместе с JSON игры выбранную сторону игрока в одной транзакции IndexedDB. Автосохранение и ручная позиция занимают два независимых слота. Последовательная запись и проверка ранее прочитанного значения внутри транзакции защищают существующую позицию от запоздавшей записи. При ошибке транзакции интерфейс сообщает об ошибке, предыдущая запись остаётся доступной.
